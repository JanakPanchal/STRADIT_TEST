Quick start

The Overview page shows a live checklist. In short:

  1. Onboard colleges (Colleges). Candidates pick theirs when they register.
  2. Create a test for each stage in the Test Center. It starts as a draft.
  3. Add questions with the builder or by uploading a file.
  4. Publish. The Review step catches mistakes first (for example, a cutoff nobody can reach).
  5. Add candidates one by one or by CSV. Download the generated passwords; they are shown only once.
  6. Assign tests by batch or by ticking candidates.
  7. Monitor progress in Candidates, and review integrity signals after the test.
Before a real drive: run a practice round with a few volunteers on the actual lab machines, and test a coding question end to end.
Colleges
  • Onboard a college with its name, a short unique code (used in CSV uploads, e.g. IITB), location, website and the placement contact. Only active colleges appear on the registration form, and only their names are public.
  • Hide a college by editing it and un-ticking Active. Existing candidates keep it.
  • Delete a college only when it has no candidates; otherwise you are asked to move them to another college first.
  • Once at least one college exists, registering candidates must choose one. In CSV uploads, the college column takes the exact name or code; an unknown value skips that row with a clear reason.
Test Center

Layout. The left list shows every test with a Live/Draft dot; search it or filter by status and stage. The workspace on the right has a three-step bar (Settings, Questions, Review & publish) that shows what is done, and a Publish button that is always in reach (it explains why it is disabled). Every step has its own address, for example /admin/test-center/3/questions, so you can bookmark or share it.

Question builder. Add question opens a panel with a live candidate preview beside the form, so you see exactly what candidates will see while you type. In the bank you can search, filter by difficulty, duplicate a question, and select several to delete. Use Save & add another to enter questions quickly. Import file takes a dragged-in CSV or JSON, validates and previews it first.

Click ＋ New test and pick the type. Choose + Aptitude, + Behaviour or + Coding; the stage decides the question type and cannot change later.

StageQuestion typeScored by
AptitudeMCQ, one correct optionMarks per correct answer
BehaviourLikert statementsSum of the score on each chosen option (no right answer)
CodingProgramming problem with test casesMarks × (cases passed ÷ total cases), best submission

1 · Settings

  • Cutoff is the number of marks a candidate must reach to unlock the next stage.
  • Opens / Closes (optional) define the window. A late starter's timer never runs past the closing time.
  • Warnings before auto-submit is the proctoring limit for this test.
  • Questions per candidate: leave empty so everyone gets all questions, or enter a number so each candidate is drawn that many at random from the bank. Use a bank at least 2–3× that size, and equal marks per question for a fair comparison. Order and option positions are always shuffled per candidate.
  • Show result controls whether candidates see their score after submitting.

2 · Questions — build one at a time, or upload a list (next section). The builder is specific to the type:

  • MCQ: add or remove options and select the correct one.
  • Likert: pick a scale preset (5-point agreement, frequency, 4-point forced, 7-point, custom). Tick Reverse-scored for negatively worded statements; the scores flip automatically.
  • Coding: problem statement, input/output formats, optional starter code, limits, and a table of test cases. Sample cases are shown to candidates; hidden cases are used only for scoring and are never revealed. Add several hidden cases, including edge cases.

3 · Review & publish — shows totals and warns about problems. Publishing is blocked when there are no questions, when the cutoff exceeds the marks a candidate can score, or when questions per candidate exceeds the bank.

Questions are locked once any candidate has started a test, so every candidate is judged on the same material. Duplicate the test to change questions for a new run. You can still edit settings, or unpublish to hide a test.

Uploading questions

In the Test Center, Questions step, choose Download template, fill it in, then pick the file. It is validated and previewed first; if any row is invalid nothing is imported and every problem is listed by row number.

Aptitude (CSV) — options separated by |; correct is the 1-based number of the right option.

type,body,options,correct,marks,difficulty
mcq,What is 15% of 200?,20|25|30|35,3,1,easy

Behaviour (CSV) — scores must have one score per option.

type,body,options,scores
likert,I stay calm when a deadline moves up.,Strongly disagree|Disagree|Neutral|Agree|Strongly agree,1|2|3|4|5

Coding (JSON) — a list; each problem needs at least one sample and one hidden case.

[{ "type": "coding", "body": "Print the sum of two integers.", "marks": 10,
   "input_format": "Two integers on one line", "output_format": "One integer",
   "test_cases": [
     {"input": "1 2",  "expected_output": "3",  "is_sample": true},
     {"input": "10 20","expected_output": "30", "is_sample": false} ] }]

Files must be UTF-8 and at most 2 MB (1000 questions). Spreadsheet formulas in text are neutralised on export.

Candidates
  • Add one candidate (choose their college from the list) or bulk upload a CSV with email,name,college,branch,batch. Passwords are generated; download them immediately. Candidates must change them at first sign-in.
  • Assign a test by batch name or by ticking rows. A candidate can have one test per stage, and stages unlock in order.
  • Invitations: instead of handing out passwords, use ✉ Invite selected or ✉ Invite all not signed in to email each candidate a link to set their own password (valid 7 days, works once, never contains a password). Sending again replaces the old link. The list shows Never signed in · invited … or Signed in … for each candidate, and the Sign-in filter finds everyone who still has not logged in. Email must be configured first (see below); in development mode the links are only written to the server log.
  • Edit changes details or deactivates sign-in. Reset password issues a new one (shown once). Delete removes the account and all results, permanently.
  • In Details: Allow retake deletes that attempt so the candidate can start again; Unassign removes an untaken test. Disqualify / Reinstate are in the Edit window.
Email setup (invitations and password reset)

Set these in the server's .env (see the README): MAIL_BACKEND=smtp, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, MAIL_FROM, and PUBLIC_URL: the exact address candidates open (for example https://assess.yourcollege.edu), because every emailed link starts with it. With the default console backend nothing is sent; the message is printed in the server log.

  • Candidates can request their own reset link from Forgot your password?; the page never reveals whether an email is registered, and an account gets at most one reset email a minute.
  • Resetting a password also unlocks the account and signs the candidate out everywhere. All of this is recorded in the audit log.
Monitoring & outcomes

The tiles at the top of Candidates count each outcome and double as filters. Combine them with batch, college, branch, assigned test, stage and stage result. Export CSV downloads exactly what is on screen.

ClearedCleared every stage assigned to that candidate.
Not clearedScored below the cutoff on a stage; not eligible for later stages.
In progressA test is running, or a later assigned stage is still to be taken.
Not startedRegistered or assigned, but no attempt yet.
DisqualifiedRemoved by an administrator.

The Warnings column is the count of proctoring violations. Reaching the test's limit auto-submits the attempt; it does not disqualify. Open Details for the time-stamped proctoring log and decide.

Integrity review

Pick a test and press Analyse. These are signals for a human to review, not verdicts.

  • Attempt flags: unusually fast high scores, many warnings, admin disqualifications.
  • Shared wrong answers (MCQ): two candidates choosing the same wrong option on many questions. Option order is shuffled per candidate, so this cannot come from copying screen positions.
  • Similar code (coding): the best accepted submission per candidate is compared after renaming variables and ignoring comments and spacing. Adjust the threshold; very short solutions are ignored on purpose. Compare shows two submissions side by side.
  • Shared start IP: normal in a lab (one address for everyone); useful mainly outside one.
Results & analytics

Choose a test to see how it went. Everything is computed from finished attempts; use View numbers as a table to see the exact figures behind every chart.

  • Summary tiles: how many completed (and how many are still running or not started), the share who cleared the cutoff, average and median score, median time against the time allowed, and how many were auto-submitted or disqualified.
  • Score distribution: how many candidates fall in each 10% band of the marks available. Black bars cleared the cutoff, grey bars did not.
  • Question analysis: for each question, how candidates did. Each question is judged only on the candidates who were served it (important when you use a question pool), and needs at least 5 of them before it can be flagged. Click a question to see how candidates answered each option.
    ▲ Too easy95% or more got it right. It does not separate candidates.
    ▼ Very hard20% or fewer got it right (or passed most test cases). Check it is fair.
    ⚑ Check keyThe most-chosen option is a wrong one. The answer key may be wrong, or the question misleading.
    ＝ No spreadA Likert statement where everyone chose the same option.
    ∅ Often skippedMore than half never submitted code for this problem.
    These are prompts to review a question, not verdicts. Questions are locked once candidates start, so use what you learn when you duplicate the test for the next run.
  • By college / by batch: completed, share who cleared the cutoff, and average score.
  • Export & shortlist: download the candidate-level CSV, optionally only those who cleared or scored at least a given mark.
Audit log

Every sign-in, test start, submission, violation batch and admin action (including deletes, resets and exports) is recorded with time and IP. Use it to answer “who changed what, and when”.

Common situations

They sign in again and press Resume. Answers and code drafts are saved on the server, and the timer kept running. No admin action needed.

Check the proctoring log in Details. If you accept the explanation, open Details and choose Allow retake for that stage. The attempt, answers and warnings are deleted and the candidate can start again.

Questions are locked for fairness. Options: duplicate the test and run the corrected version, or delete the test (a two-step confirmation shows how many attempts will be removed) and start again.

Candidates → Edit → Reset password. Give them the new password; they must change it at sign-in. An account locked after repeated wrong passwords unlocks itself after 10 minutes, and a reset also unlocks it.

The Judge0 service is unreachable. Check it is running and that its address and token in the server settings match. Candidates’ code is saved as drafts meanwhile.

Edit the name in Colleges to fix it everywhere. For duplicates, delete one and choose the other when asked where to move its candidates.
Glossary
StageOne of Aptitude, Behaviour, Coding. Taken in that order.
CutoffMarks needed to clear a stage and unlock the next.
Draft / LiveDraft tests are invisible to candidates; Live (published) tests are visible to those assigned.
Question bank / poolAll questions in a test. With Questions per candidate set, each candidate is drawn a random subset.
WarningA counted proctoring event (leaving fullscreen, switching tab, copy/paste, developer tools).
Auto-submitThe test is submitted when time ends or the warning limit is reached.
Sample / hidden caseSample cases are shown to candidates; hidden cases only score submissions.
OutcomeThe overall status of a candidate: Cleared, Not cleared, In progress, Not started, Disqualified.
