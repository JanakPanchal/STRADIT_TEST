Candidate guide

How the assessment works

Read this once before your test. It takes about five minutes.

1 · Before you start
  • Use a desktop or laptop with a current Chrome, Edge or Firefox. Phones and tablets cannot run the test (they cannot hold fullscreen).
  • Use a stable connection and close other windows, chat apps and screen-sharing tools. Keep your charger plugged in.
  • Sit somewhere quiet. You must work alone, with no notes, phones or other people.
  • On the rules page before each test there is a System check. If anything is red, fix it first.
2 · Signing in
  • Registering yourself: choose your college from the list, then your branch and batch. Your password needs at least 8 characters.
  • Invited by email: open the link in your invitation, choose your own password, then sign in. The link works once and expires after 7 days. If it has expired, use Forgot your password? or ask the administrator to send a new invitation.
  • Account created with a temporary password: sign in with it; you will be asked to choose a new password straight away.
  • Forgot your password? On the sign-in page choose Forgot your password?, enter your email and open the link we send (valid for 30 minutes, works once). Nothing arrived? Check spam and wait a minute; for your security the page says the same thing whether or not the email is registered. The administrator can also reset it for you.
  • After 5 wrong passwords the account is locked for 10 minutes. Wait, then try again.
3 · The three stages
Stage 01
Aptitude
Multiple choice
Stage 02
Behaviour
Statements, no right answer
Stage 03
Coding
Write and run code
  • Stages are taken in order. A stage unlocks only when you reach the qualifying score of the previous one. The score you need is shown on the rules page.
  • If your score is below the qualifying score you are not eligible for later stages. Your dashboard will show this.
  • Behaviour questions are statements such as “I stay calm under pressure”. Choose the option that is true for you. There are no trick answers; answer honestly and consistently.
  • You get one attempt per stage. Only an administrator can allow a retake.
4 · During a test
  • Click Start on your dashboard, read the rules, tick the agreement and press Start test. The test opens in fullscreen.
  • The timer at the top is kept by the server, so changing your computer clock does nothing. When it reaches zero your test is submitted automatically.
  • Answers save automatically when you choose them. Use the numbered buttons on the side to jump between questions. Green means answered. Clear answer removes your choice.
  • Questions and options may appear in a different order from other candidates. That is intentional. Some tests also give each candidate a different set of questions.
  • When you finish, press Submit test and confirm. You cannot change answers afterwards.
  • If your browser or computer crashes: sign in again and press Resume. Your answers and the timer are exactly where they were. The time while you were away still counts.
5 · Rules & warnings

The test watches for behaviour that can indicate cheating. Each of these is recorded as a warning with a time stamp that the administrator can see:

  • Leaving fullscreen (including pressing Esc)
  • Switching to another tab or window, or clicking outside the browser
  • Copy, cut or paste (except inside the code editor, see section 6)
  • Opening developer tools or using blocked shortcuts

What happens at the limit

Your test shows how many warnings you have. When you reach the limit, the test is submitted immediately and flagged for review. A single action that triggers several events at once (for example, switching tabs) counts as one warning. Resizing the window is recorded but is not counted.

You can be disqualified by the administrator for impersonation, getting outside help, using a second device, or tampering with the test page. Disqualification applies to the whole recruitment drive.

If you exit fullscreen by accident, a screen appears with a Return to fullscreen button. Press it straight away.

6 · The coding playground

Coding questions open a workspace with the problem on the left and an editor and console on the right.

  1. Read the problem. It lists the input format, output format, limits and sample cases. Your program must read from standard input and write to standard output. Do not print anything extra (no prompts like “Enter a number”).
  2. Pick a language in the toolbar (Python, Java, C++, C or JavaScript). Each language starts with a template. Your code is kept separately per language, and everything is autosaved to the server, so a refresh or crash loses nothing. Saved 10:42:05 next to the toolbar shows when.
  3. Run samples Ctrl/⌘ + Enter tests your code on the sample cases and shows Input, Expected output and Your output side by side, plus time and memory. Use it as often as you like (there is a short per-minute limit).
  4. Custom input tab: type your own input and press Run with this input to see what your program prints. Great for edge cases such as zero, negative numbers, very large values.
  5. Submit Ctrl/⌘ + Shift + Enter judges your code against all test cases, including hidden ones that are never shown. You see how many passed. You can submit again; your best submission counts. The Submissions tab lists your attempts.
  6. Remember to Submit. Running samples does not score anything. Only a Submit counts towards your marks.

What the verdicts mean

AcceptedYour output matched on every case that was checked.
Wrong AnswerYour program ran but printed something different from the expected output. Check spacing, line breaks and rounding.
Time Limit ExceededIt took longer than the limit. Look for a loop that is too slow; try a faster approach.
Compilation ErrorThe code did not compile. The message is shown under Errors. Fix the syntax and run again.
Runtime ErrorThe program crashed (for example divide by zero, index out of range, reading input that is not there).

Editor tips

  • A− / A+ change the text size; ◐ switches the editor between light and dark; Reset restores the starter template for the language you are using.
  • Copying inside the editor works (cut, copy and paste your own code). Pasting anything from outside the editor is blocked and logged as a warning, and so is dropping text onto it.
  • The editor does not auto-complete or suggest code. This is intentional so everyone has the same conditions.
7 · Troubleshooting

Tick the agreement checkbox first. If the System check shows a red item, fix that item (for example use a desktop browser, or allow cookies), then press Run check again.

You left fullscreen (often by pressing Esc). That counted as a warning. Press Return to fullscreen straight away. Avoid pressing Esc or opening other windows during the test.

Reconnect, reload the page and sign in if asked, then press Resume. Everything you selected is saved. The timer kept running while you were offline, so resume quickly. If a message says “Could not save answer”, your connection is unstable; check it before continuing.

The test was already submitted (by you, by the timer, or by reaching the warning limit). There is one attempt per stage. Ask the administrator if you believe this is a mistake; only they can allow a retake.

A locked stage means you have not yet cleared the previous one. “Not open” means the test window has not started; the opening time is shown on your dashboard. “Closed” means the window has ended.

Use Custom input to run the exact sample. Make sure you read from standard input, print only the answer, and that Java’s class is named Main. A stray debug print or a missing newline is the most common cause of Wrong Answer.

The server that runs code is busy or down. Wait ten seconds and try again; your code is saved. If it persists, tell the invigilator, who will contact the administrator.

Still stuck? Tell the invigilator in the room, or contact the administrator who invited you. Do not close the test tab.

8 · After the test
  • Some tests show your score straight away; others only confirm that your answers were recorded. The administrator decides.
  • Your dashboard shows each stage as Cleared, Not cleared or In progress. You are Cleared overall once you clear every stage that was assigned to you.
  • Final shortlisting is done by the recruitment team.
